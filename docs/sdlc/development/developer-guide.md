<!-- sdlc:auto:start overview -->
wedgw is a weight-and-height tracker for kids, generated by the Quorq AI SDLC platform as two separate apps in one repo. The `frontend/` is a Vite + React 19 SPA whose screens were all design-approved and currently render seeded sample data rather than live API calls. The `backend/` is a FastAPI 0.115 service scaffolded from no approved architecture yet, so it only exposes a `/health` endpoint and uses SQLAlchemy models (currently empty) against a SQLite database by default, with Postgres 16 available via docker-compose for a closer-to-production setup.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for Vite 6 / React 19 frontend tooling)
- Python 3.12
- pip
- Docker (optional, for the docker-compose Postgres service)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd frontend && npm install
3. cd backend && pip install -r requirements.txt
4. (optional) copy .env.example to .env and adjust values such as DATABASE_URL / ALLOWED_ORIGINS
5. (optional) run `docker-compose up db` from the repo root if you want Postgres instead of the default SQLite file
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routers are generated one per approved architecture component that owns endpoints, under backend/app/routers/
- Every generated backend route returns a typed StubResponse placeholder until implemented, keeping the service startable and OpenAPI complete
- SQLAlchemy models all inherit from the shared Base in app/database.py; main.py imports models before calling Base.metadata.create_all
- Backend defaults to SQLite (sqlite:///./app.db) via DATABASE_URL env var, switchable to Postgres/other via the same var with no code changes
- CORS allowed origins come from the ALLOWED_ORIGINS env var (comma-separated), falling back to local Vite dev origins
- Frontend screens live one module per approved screen under src/screens/, built against the shared component/icon vocabulary in lib/ui.tsx and lib/icons.tsx
- Frontend API calls go through the single apiFetch helper in src/lib/api.ts, which attaches a bearer token (session token or shared secret) and prefixes VITE_API_BASE_URL
- Frontend unit tests (Vitest) sit beside the components they cover; Playwright e2e specs live separately in e2e/
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the backend are blocked by CORS | Set the ALLOWED_ORIGINS env var on the backend to include the frontend's origin, or rely on the default localhost:5173/127.0.0.1:5173 dev origins |
| `npm run build` succeeds but `tsc` fails later in CI/deploy | Run `npm run typecheck` locally to catch type errors the build step skips |
| `npm run test:e2e` can't start the backend | Playwright's webServer expects a Python venv at backend/.venv; create it and install backend/requirements.txt there before running e2e tests, or set E2E_BASE_URL to point at an already-running deployment |
| Backend fails to connect to a database | Backend defaults to a local SQLite file (app.db) requiring no server; if DATABASE_URL points at Postgres, start it first with `docker-compose up db` |
| Playwright browsers not installed | Run `npm run test:e2e:install` in frontend/ to fetch Chromium before `npm run test:e2e` |
<!-- sdlc:auto:end troubleshooting -->
